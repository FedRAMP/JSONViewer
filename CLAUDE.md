# CLAUDE.md

Guidance for the `viewer/` app. It is fully independent of `../editor/` — no shared code, its own `package.json`/`bun.lock`/`public/`. Run all commands from `viewer/`; see `README.md` for the command list.

## Architecture

Plain Vite + vanilla JS (no React). `index.html` holds the toolbar markup; `src/main.js` wires it up:

1. Load `public/fedramp-consolidated-rules.json` + the common-definitions schema, then every `SCHEMA_CATALOG` entry (`src/config.js`) via `src/utils/schemaLoader.js` (local first, GitHub raw fallback). Each schema gets `inlineCommonDefs` (`src/utils/schemaRefs.js`), `patchFRMRSchema` (`src/utils/frmr.js`) and `patchRV5Schema` (`src/utils/rv5.js`) so requirement/control IDs carry `enumNames` titles.
2. On file open/drop: parse JSON, `detectSchema` (`src/utils/detectSchema.js`) picks the document type, user can override via the dropdown.
3. `buildPreviewHtml` (`src/utils/htmlPreview.js` + `.css`) renders a standalone HTML page into `<iframe sandbox="">`. Keep the sandbox empty — it's the XSS defense for untrusted input files.
   Every level is a native `<details>` (top sections, nested object/array sub-sections, array items), so the tree collapses/expands without script. Array items put their ID (an `…Id`/`…ID` field) and any `…Status` enum as a colour-coded badge in the `<summary>` and omit those rows from the body. Arrays whose items all have hyphenated IDs are grouped into collapsible family boxes (first ID segment, e.g. `AFC`/`MKT`/`AC`, or first two when all share the first, e.g. `KSI-CED`), named from FRMR via `extractFamilyNames` (`src/utils/frmr.js`) passed as `options.groupNames`. Default render: everything open except item cards directly inside a family group (closed); `options.expanded`/`options.collapsed` open/close everything. The toolbar's Expand all / Collapse all re-render via `buildPreviewHtml(..., { collapsed })`, since the sandboxed iframe can't run script.

### Control Guidance view

A second view (toolbar toggle **Document / Control Guidance**) needs no opened file: it renders `public/AgencyControlGuidance.controls.merged.json` (`{ controls: { FAMILY: { "AC-02": { parts: { a|_: { agency_actions, fedramp_guidance, notes } } } } } }`, hand-maintained — not fetched by `bun run sync`) via `buildControlGuidanceHtml` (`src/utils/controlGuidance.js`). Each control card gets a "Mapped FedRAMP Rules" subsection listing every FRR/KSI whose FRMR `controls` array cites it; `extractControlRuleMap` normalizes FRMR's OSCAL-style ids (`at-2.2`) to the guidance file's keys (`AT-02 (02)`) via `toGuidanceControlId`. Both views share `wrapPage`/CSS from `htmlPreview.js`. If the guidance file fails to load, the toggle is disabled. Control headers show NIST titles from `public/nist-800-53-rev5-control-titles.json` (`{ "AC-02 (01)": "Automated System Account Management" }`, keyed like the guidance file), generated by `scripts/sync-control-titles.js` (`bun run sync:titles`, also run by `bun run sync`) from NIST's OSCAL SP 800-53 Rev 5 catalog pinned to a commit; enhancements render as "Base Title | Enhancement Title" (`controlTitle`). When a document is open in the Document view, `buildItemCardIndex` (`htmlPreview.js`) renders its ID-identified array items (an SDR's `frrID`/`ksiId`/`controlId` entries) as the same cards the Document view shows, keyed by ID, and `buildControlGuidanceHtml` embeds the matching card under each mapped rule (`options.sdr = { label, cards }`), or a "Not in <file>" note.

`config.js`, `schemaRefs.js`, `frmr.js`, `rv5.js`, `schemaPatch.js` and `scripts/sync-public.js` are copies of the editor's versions; keep them in step manually when either side changes. Intentional divergences: the viewer's `patchFRMRSchema` also patches `ksiId` with KSI titles (the editor keeps `ksiId` free-text), and the viewer-only `extractRuleForces`/`formatForceByClass` read each rule's `force` (directly, or per class under `varies_by_class`, collapsed like "A: SHOULD · B–D: MUST") for the force-of-rule badge in item summaries (`options.ruleForces`). `extractRuleTexts` (built on the shared `ruleStatements`/`ruleForce` helpers in `frmr.js`) feeds `options.ruleTexts`, which adds a collapsible "FedRAMP Rule" section (statement(s), per class when they vary, plus any `following_information`) at the top of each matching item card in the Document view; it starts closed and opens with Expand all. `renderRuleText` in `htmlPreview.js` renders that text for both views. The Control Guidance view doesn't pass `ruleTexts` to `buildItemCardIndex`, since its rule cards already show the text.

## Testing

- `bun run test` — Vitest (`tests/`): renderer output, schema detection against `public/samples/*`, `$ref` inlining, enum patching. Per-sample detection checks are skipped for any sample that no longer carries its own schema's required keys (fixture drift after a schema sync).
- `bun run test:e2e` — Playwright (`e2e/`), boots `bun run dev` on port 5174: every sample renders with no console errors, auto-detection, manual type override, invalid-JSON handling.
